# (docs/design/dispatcher.md §7, As built: the brief template).

# `aries dispatch brief ID` for a coordinator to send to a Desktop session.

# is kept only for that harness, without the tag. The slots are {id},

# is only a slot rendering empty is dropped.

# A change to any line below the version ships by review and raises the
# version; scripts/brief_test.go fails until it does, and `go test
# ./scripts/ -run TestBriefTemplate -update` then records the new one.

[desktop] You are a session the project's coordinator started on issue {id}.

Do this:
[headless] 1. Call the aries MCP tool `prime`, then `start` with id {id}: the claim is already yours, taken in this session before you started.
[desktop] 1. Call the aries MCP tool `prime`, then `start` with id {id}, and read it in full (`show` with `full`).

[headless] 3. Work only in this worktree, {worktree}, on the branch {branch}. Never touch another checkout, and never run git in the main one.
[desktop] 3. Work only in your own worktree, on a branch from origin/main named {branch}. Never touch another checkout, and never run git in the main one.

[headless] 7. This run is headless and has no Auto-fix: say so in your handoff, and end after it. The sweep, and until it ships the coordinator, takes over the PR's CI failures and conflicts.
[desktop] 8. Stop every background command and monitor you started before your handoff.
[headless] 8. Start no background work: a headless run waits for it before exiting.
9. If your claim's lease lapses, `start` {id} again before writing to it.
10. Before your handoff, post your lessons as the memory `lessons` says.
11. When the PR is open, call `handoff` with state `done`, the PR's link in the note and `ticked` for the items you met. Never call `finish`; never merge.
