# Aries v0.7.0

Decisions are named beside the items they settle
([design §14](../design/aries.md#14-decisions)).

## Summary

v0.7.0 is the minor release after v0.6.0 (decision 93). It upgrades in
place, with one schema migration (migration 3, which adds the price
tier to `prices`), and it speaks protocol 10 and accepts 9 and 10:
`ProtoMin` moves to 9, so v0.5.0's `aries` is no longer served.

What it adds: prices by prompt length (Claude Haiku 5.5 over 100,000
tokens); three experimental, CLI-only parts of the agent factory, the
dispatcher (`aries dispatch`), the outcome record (`aries outcome`) and
the guard (`aries guard`); the scheduled pull job (`aries setup
pull-job`); the merge rule's read-only verdict (`aries prs merges`); a
help listing with an Experimental heading and `aries help hooks`; one
`workflow` group and `--pubkey`; ariesd instruments for issue cycle
time, closes and reopens, queue, landing and gate waits, live claims
and the ready queue, with two dashboards; Sextant's cost by account,
tokens and hours, with alert rules and a dashboard; and the export of
Claude Code's own metrics, without content. And fixes: three of the
v0.5.0 security review's minor findings, and the Go toolchain moved to
1.27.3 for GO-2026-6809.

## Read first

- **The protocol is 10, and v0.5.0's clients stop working.** `aries`
  v0.7.0 speaks protocol 10; `ariesd` v0.7.0 accepts 9 and 10. v0.6.0's
  `aries` keeps working against a v0.7.0 server (rule 10, decision 93);
  v0.5.0's (protocol 8) is refused at the handshake with code `version`,
  exit code 3, and told to run `aries upgrade`. `aries` v0.7.0 against a
  v0.6.0 server is refused the same way, with a line saying to upgrade
  the server. Protocol 10 is this release's one bump: `price.set` takes
  `tier` ([Prices by prompt length](#prices-by-prompt-length)).
- **Upgrade `ariesd` first, then `aries`.** `ariesd upgrade` on the
  server, then `aries upgrade` on each machine, in that order. The
  server migrates each project's schema when it starts (migration 3);
  a server of many
  projects with many large schemas can take longer to start, which the
  systemd unit allows for. Nothing else is needed: no change to a config
  file, and the release key is v0.5.0's. An older `ariesd` refuses a
  database this one migrated.
- **A server whose clients include v0.5.0's must upgrade them first.**
  The window the v0.6.0 notes left open, a relay taking a protocol 8
  client's unbound key proof, is closed by refusing protocol 8
  ([Security changes](#security-changes)).
- **The experimental commands change what an unattended agent may
  run.** Read [The guard](#the-guard-experimental-and-cli-only) before
  running `aries dispatch run`; it will not start a run in a repository
  with no `.aries/guard.yaml`.

## What's new

### Prices by prompt length

- **A price may carry a tier** (aries-itlyj3yw; protocol 10).
  `aries admin price set … --over TOKENS --over-input USD …` gives the
  rates for a request whose prompt (input, cache writes and cache
  reads) is over that length, as Claude Haiku 5.5 is billed (five times
  the rates over 100,000 tokens). Each request record is priced on its
  own; records that sum a turn or session carry no prompt length and are
  priced at the base rates. Cost is still computed when read. Migration
  3 adds the tier to `prices`. A server operator sets the tier with the
  command in [docs/server.md, Prices](../server.md); no price is set by
  the release. Not priced: `inference_geo`'s 1.1x.

### The guard, experimental and CLI only

- **`aries guard`** (aries-qdb5xj4w; design [guard.md](../design/guard.md),
  PRs 299, 315 and 316). One policy file, `.aries/guard.yaml`, read by a
  PreToolUse hook (`aries guard --hook`) over Aries's own `sh` parser on
  the standard library: it reads every simple command through
  `VAR=value`, `env`, `sh -c`, `xargs`, `find -exec` and the other
  wrappers, and what it is unsure of it denies, with a fix on each denial
  that never quotes the command (a denial is counted, with its rule, in
  `guard/denials.jsonl`). `aries guard --check [COMMAND…]` tries a
  command against the policy. It is not a sandbox.
- **Every session runs it.** `aries setup claude-code` writes the hook
  and a coarse copy of the policy's denies in `permissions.deny` for a
  project (not `--global`), `--check` and `--remove` know them, and
  `aries prime --hook` snapshots the policy for the session. A session
  fails open in Claude Desktop, with a one-line note, and a headless run
  fails closed. The hook is written so that an `aries` older than the
  guard (exit 2, which Claude Code reads as "block") cannot block every
  call: it falls back to a message and `onFailure: "continue"`, and
  `setup --write` refuses to write it when the `aries` it would run
  cannot run it.
- **The dispatcher uses it** and its Go lists, `DefaultAllowed` and
  `DefaultDenied`, are gone: at each launch it snapshots the policy of
  the default branch and renders `--allowedTools`, `--disallowedTools`
  and its own hook with `onFailure: "block"` from it; with no policy, or
  one that does not load, no run starts. Not built: the check that
  Claude Code is a version that honors `onFailure` (2.1.295 or later).
  This repository's own `.claude/settings.json` does not run the guard
  yet.

### The dispatcher, experimental and CLI only

- **`aries dispatch run|status|stop|brief`** (aries-emlsyvmv, PR 278,
  reapplied after v0.6.0 in PR 283; decision 96). The client-side
  dispatcher's loop ([dispatcher.md](../design/dispatcher.md)), on macOS
  and Linux, with `--dry-run`: it picks ready issues by their model
  label, claims each before launch, starts headless runs within the
  `dispatch/runs` lock and the budget cap, and stops on `stop`, the
  `dispatch/pause` lock, two CI failures or the cap. Its after-merge
  sweep is not in it (aries-i6fndp4h), so a run's failing PR has no
  owner but the coordinator.
- **Scope and wake.** `--models` and `--labels` limit a run to a subset of
  ready issues; the loop judges every ready issue, up to the 500 one
  answer holds, not the first 20; it wakes when `dispatch/pause` is
  released or a slot of `dispatch/runs` frees; a `partial` or `blocked`
  handoff whose PR is open is skipped as `awaiting-review`; and an issue
  that names `internal/server/keys.go` is no longer taken for release
  signing work.
- **Runs.** A run starts under `aries lock run --grace 40s`, the new
  flag that gives its command longer to flush after the interrupt; with
  `GOTOOLCHAIN=local`, `GOFLAGS=-mod=readonly`, Postgres on `PATH` and
  `ARIES_REQUIRE_POSTGRES=1`; in a fresh worktree from `origin/main`,
  moving a lost run's tree to `PATH.lost-SHA` instead of reusing it; and
  a run's branch is deleted once its PR merged or the remote has its
  head, retried at each wake. A CI result is counted once per PR and
  commit, a dry run writes no log, and `status` calls a run live only
  while its process runs. With `ARIES_AGENT_OTLP_ENDPOINT` set, a run
  exports Claude Code's metrics ([Metrics](#metrics)).
- **One versioned brief.** `.aries/brief.txt` is the template of a
  worker's steps (version 3 here), rendered for a headless run and, by
  `aries dispatch brief ID`, for a Desktop session, with the `brief:`
  record's first line as `key=value` fields and one hash rule
  (`internal/brief`); `scripts` holds each version to a golden file. Version 3
  tells workers to leave the CI and the review and merge items open at
  handoff, to wait for a long command inside the turn, and to run
  commands bare.

### The outcome record, experimental and CLI only

- **`aries outcome`** (aries-4x4vo7cq, PR 277, reapplied after v0.6.0).
  For an issue that reached an outcome, it gathers the per-run outcome
  record ([outcome-record.md](../design/outcome-record.md)) from Aries
  and the CI host through `gh`, and posts it once as an `outcome:`
  comment; `--dry-run` prints it, `--backfill --since` covers the past.
  It matches a brief to the run whose `session=` names it. The learning
  loop's primary signal (epic aries-dmqqolg4).

### Landing and merging

- **`aries setup pull-job` and `aries pull-job --run`** (PR 300): a
  scheduled pull that lands, for a server CI cannot reach: a launchd
  agent, a systemd user timer or a Task Scheduler task, every 15 minutes
  by default. It fast-forwards the default branch only with no change to
  a tracked file, then runs `aries land` from the session `cli` on
  every run, not only after its own pull. `--check` and `--remove` know
  only the job's own files ([docs/ci.md](../ci.md)).
- **`aries prs merges [--rules FILE] [PR…]`, CLI only** (PR 326, slice M1
  of [merges.md](../design/merges.md)). One line for each open pull
  request, `queue` or `hold` with the first condition that failed, read
  only: it queues and merges nothing. The product's floor (releases and
  signing, CI workflows, dependency files, what agents may run, the rule
  file itself) is built in, the repository's rule is `.aries/merges.yaml`
  read from the default branch, and it fails closed. An opener it cannot
  verify never queues. `--queue`, the server setting and the freeze lock
  are not built.
- **A forced close records `folded_into`** (PR 302): the issues a closed
  issue's `duplicates` and `supersedes` links name, so that an admin's
  `close --force` of a duplicate says what it was folded into.

### The command line

- **`aries help`** has an Experimental heading (`dispatch`, `outcome`,
  `guard`), moves `mcp`, `usage` and `pull-job` behind `aries help hooks`,
  and marks a person's commands. `help bogus` exits 2.
- **`gate`, `lock` and `dispatch` read `--json` before an action**, print
  a flags block, and `create --id` is hidden (PR 323).
- **`workflow`** holds `show`, `diff`, `check` and `set`; `admin workflow`
  runs the same code. **`admin principal add --pubkey`** replaces
  `--key`, which still works, hidden, with a line on stderr. **`tick`**
  is a hidden alias of `accept`. The listing's commands are held to
  `internal/cli/testdata/help-listing.golden` (PR 325).
- **MCP wording** (PRs 319 and 322): the server's instructions, the tool
  descriptions and the pointer block `aries setup` writes steer an agent
  to `handoff` with state `done`, not `finish`, and not to waive an
  item that a check or a person settles. No tool changed.

### Metrics

- **New ariesd instruments** (names are kept from here,
  [Names that are kept](../server.md#names-that-are-kept)):
  `aries.issue.cycle.duration`, `aries.issue.queue.duration`,
  `aries.issue.landing.duration` and `aries.gate.wait.duration`
  (histograms); `aries.issues` and `aries.issues.ready` and
  `aries.claims.held` (gauges); and `aries.issues.closed` and
  `aries.issues.reopened` (counters, by reason). The ready gauge counts
  with one anti join (31 ms at 50,000 issues, not 1.2 s) and is cached
  for a minute. Two dashboards: "Aries work" (flow, closes, rates,
  waits) and, from Claude Code's own metrics, "agents".
- **Sextant X1 and X3** (PR 303): `sextant.account.cost.usd`,
  `sextant.hours`, `sextant.tokens` and `sextant.cost.unpriced.tokens`,
  with alert rules (an account over budget, unpriced tokens, the
  exporter failing) and a dashboard. Accounts beyond 20 are `(other)`.
  Still built from source ([Running Sextant](../sextant.md)); amortized
  cost, the rules that wait on flow (X2) and a release (X5) are not.
- **Claude Code's metrics, without content** (PR 305): the environment
  and a settings block that have Claude Code export its metrics and
  events to the Collector as `aries-agents`, with `session.id` joining
  them to Aries; a test fails if a variable that adds content is set
  (`internal/agenttel`, [docs/agents.md](../agents.md)).

## Fixes

- **Refusal log lines are sampled by address and reason** (finding P-2
  of the v0.5.0 security review, PR 306): behind a proxy, one client
  looping refused key proofs no longer hides every other refusal from
  the journal. Metrics are unchanged.
- **`client_secret_file` is read from the file that was opened** (finding
  S-3, PR 304): the mode is checked on the open file, which is read once,
  at most 1 MiB. Sign-in ships off unless configured.
- **A dispatcher that stops a run** now waits the 40 seconds it asks
  for, not 10 (PR 307); the other dispatcher fixes are listed above.
- **A queued MCP call's answer carries the entry's idempotency key**
  (PR 329, aries-fpxpal46): in its structured content, as `key`, so a
  caller can name the queued write. A new result field only, which
  clients ignore; not breaking. It fixed a race in the partition soak's
  own bookkeeping, present since 16 Oct, which was not in the product.
- **An issue folded into a duplicate** no longer stays in ready without
  a way to close it ([Landing and merging](#landing-and-merging)).

## Breaking changes

- **`aries` v0.7.0 needs a v0.7.0 server.** Against a v0.6.0 `ariesd` it
  is refused at the handshake with code `version`, exit code 3, and a
  line saying to upgrade the server.
- **v0.5.0's `aries` is refused by a v0.7.0 server** (`ProtoMin` 9), with
  the fix `aries upgrade`.
- **`aries dispatch run` needs `.aries/guard.yaml`** on the default
  branch, and no longer takes `DefaultAllowed` and `DefaultDenied`
  from Go. Experimental.
- **A dispatcher state file** written before PR 293 can hold one CI
  failure counted twice until `aries dispatch run --clear`.

## Security changes

- **v0.5.0's clients and the unbound key proof are no longer served.**
  `ProtoMin` is 9, so a v0.7.0 `ariesd` refuses protocol 8's `aries`,
  whose key proof binds nothing of the TLS session, and the window the
  v0.6.0 notes called not covered (finding K-2) is closed for every
  client the server serves. `https: refuse_key_proof_v1` has nothing
  left to refuse.
- **The guard** denies what an unattended agent may not run: releases,
  signing, merges and pushes to `main`, and what the policy lists, from
  one file, however a command is wrapped. It is a policy over what the
  hook is shown, not a sandbox ([guard.md §10](../design/guard.md)).
- **Findings P-2 and S-3** of the security review are fixed
  ([Fixes](#fixes)).
- **Go 1.27.3** (PR 297): govulncheck's GO-2026-6809, in
  `crypto/x509`, reached through `wsconn.Dial`, failed every lint job on
  1.27.2. Every pin moved together. The released binaries are built
  with it.
- The rest of the review's minor findings, L-5 (a rate on new HTTPS
  connections from one address), stays for a later release.

## Removals

- **`DefaultAllowed` and `DefaultDenied`** of the dispatcher; the guard's
  policy replaces them.
- **`admin principal add --key`** is deprecated, not removed.

## Supported platforms

| Part | Platforms |
|---|---|
| `aries` | Linux, macOS and Windows, on amd64 and arm64. The outbox and the cache have not run on Windows. `aries dispatch` runs on macOS and Linux; `aries guard`, `outcome` and `prs` need no scheduler, and `pull-job` uses launchd, systemd or Task Scheduler (not run on Windows) |
| `ariesd` | Linux, on amd64 and arm64. Supported: Ubuntu 24.04 LTS and 26.04 LTS. Systems that run SELinux are not supported yet |
| `sextant` | Built from source, for Linux, macOS and Windows; meant to run on the server's machine. No release asset (X5) |
| Database | Postgres 16 or newer, on the machine or another, or a managed service. The tests pin Postgres 18.6 (`version.Postgres`), unchanged; the installer installs 18 from the PostgreSQL project's apt repository (decision 81) |
| Agents | Claude Code, Codex, Gemini CLI, Cursor, VS Code, Junie, JetBrains AI Assistant and Claude Desktop, through `aries setup`. The guard's hook is Claude Code's PreToolUse; Codex and Gemini have designs only, and Cursor, VS Code and Junie none |
| Identity providers | None promised: keys only (decision 91). Sign-in through an OpenID Connect provider and service principals stay as in v0.5.0, off unless configured and untested against a real provider |
| Transports | HTTPS by default; SSH when an operator turns it on (decision 86) |
| Go toolchain | 1.27.3 (building from source) |

## Not in this release

Each names its Aries issue where it has one:

- ACME against a real certificate authority (aries-pk55wedb); it has run
  only against a test CA.
- A rate on new HTTPS connections and TLS handshakes from one address,
  finding L-5 (aries-bt467whn).
- Lessons as a field on `handoff` and `finish` (L2, aries-l436tgkj), and
  recorded briefs in the store (aries-2qx4mlm2): a `lesson:` and a
  `brief:` are still comments.
- The dispatcher's after-merge sweep (aries-i6fndp4h), `aries prs merges
  --queue`, the merge rule as a server setting (M2 and M3), and Bearings,
  which is a design only.
- The guard for Codex and Gemini, and the Claude Code version check for
  `onFailure: "block"`; this repository's own settings do not run it.
- Sextant's flow rules (X2), amortized cost, and a release (X5).
- What v0.5.0's notes list for before v1.0.0 and for 1.x
  ([Not in this release](v0.5.0.md#not-in-this-release),
  [Coming in 1.x](v0.5.0.md#coming-in-1x)) still stands.

  **`internal/agenttel`** are new packages, with rows in AGENTS.md's
  layout; `scripts/brief_test.go` holds the brief's versions.
- **`TestHelpListing`** holds the listing to a golden file: a new command

  [merges](../design/merges.md), [factory-review](../design/factory-review.md)

## What the release candidate ran

On `main` at `55332ef`, on 22 October 2026, on a Mac (arm64) with
Go 1.27.3 and Postgres 18.6:

- **The soaks**, 10 minutes of work each under `-race`: the long soak
  over SSH, over HTTPS (`ARIES_E2E_TRANSPORT=https`), with the telemetry
  check, refused, and the flood soak, all passed. The partition soak
  failed at `55332ef` (seed 4544211327894935511): a race in the soak's
  own bookkeeping, not the product (aries-fpxpal46). PR 329 fixed it
  (see [Fixes](#fixes)), and the same seed passed on that PR's branch.
- **`deploy/docker/smoke.sh`**, on PR 327's branch (`55332ef` and that
  PR), passed in all five modes: HTTPS, 156 checks; SSH, 169;
  telemetry, 212; identity, 207; proxy, 158. PR 327 fixed the telemetry
  mode, which failed first on the rule-file count.

The soaks and `smoke.sh` ran before PRs 327 and 329 merged, and the
commit to be tagged has not run them: see [Not verified](#not-verified).

## Not verified

What this release has not run, as of `main` at `55332ef`:

- the soaks and `smoke.sh` on the commit to be tagged, which the
  maintainer runs (`soak.yml`): they ran on `55332ef` and on PRs 327 and
  329's branches, which differ from it, and CI's gate ran each pull
  request without them;
- the installer on a real machine (aries-g446t7vk), and the
  installer's containers' limits as v0.6.0 listed them;
- the migration on a server with many or large projects, and an upgrade
  from v0.6.0 with `ariesd upgrade` itself;
- the dispatcher beyond its first live trials, which ran a few Haiku and
  Sonnet issues; it has not run unattended for long;
- the guard against every shell form: it fails closed on what it cannot
  read, and its table tests are the evidence; and Claude Code's
  `onFailure: "block"` is not version-checked;
- `pull-job` on Linux and Windows, and the scheduled pull against a
  real CI-less server for long;
- `aries prs merges` against pull requests other than this repository's;
- prices by prompt length against a real invoice, and the tier with a
  model other than Haiku 5.5;
- the scrape cost of the new gauges on a server with several large
  projects (31 ms was measured at 50,000 issues on one machine);
- ACME against a real certificate authority;
- what v0.6.0 listed and this release does not change: the outbox and
  the cache on Windows, a real network partition, Sextant outside the
  tests, a managed Postgres and a standby's failover, and sign-in
  against any real provider ([v0.6.0, Not verified](v0.6.0.md#not-verified)).
